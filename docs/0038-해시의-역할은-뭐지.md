# 0038 · 해시의 역할은 뭐지?

## Q. 해시의 역할은 뭐지?

---

**해시(Hash)**는 한 문장으로 **"길이가 제각각인 데이터를, 고정된 크기의 짧은 숫자(지문/번호표)로 바꾸는 것"**입니다.
*(원래 영어 *hash*는 감자·고기를 잘게 다져 섞는 요리에서 온 말로, 입력을 다져서 섞어 짧은 숫자로 요약한다는 뜻입니다.)*

컴퓨터에서는 목적에 따라 크게 **3가지 역할**로 쓰입니다.

---

### 1. 위치 찾기 / 빠른 색인 (지금 우리 `HashMap`의 역할)
* `"a"`든 `"very_long_user_session_key_12345"`든 길이에 상관없이 **항상 32비트 숫자 하나**로 바꿉니다.
* 이 숫자를 `% capacity`로 나눠서 **"이 데이터를 배열의 몇 번 방에 넣을지"** 즉시(O(1)) 결정합니다.
* 여러 방에 골고루 퍼뜨려 한 방에 몰리지 않게 하는 것도 이 역할에 포함됩니다.

### 2. 데이터의 "지문" (변경 확인 · Git 커밋 ID)
* 입력에서 **1글자만 바뀌어도 전혀 다른 해시값**이 나옵니다.
* 그래서 대용량 파일 전체를 일일이 비교하지 않고 해시값만 비교해서 **파일이 깨지거나 바뀌었는지(무결성)**를 금방 확인합니다.
* 우리가 방금 커밋할 때 나온 **`89a00cd` 같은 Git 커밋 ID**도 그 시점 코드 전체를 해시로 만든 지문입니다.

### 3. 비밀번호 숨기기 (암호화 해시: SHA-256, bcrypt 등)
* 해시값만 보고 원래 글자를 거꾸로 추측하기 어렵다는 성질(단방향성)을 이용해, 서버 DB에 비밀번호 원문 대신 해시값만 저장할 때 씁니다. *(우리 `fnv1a_32`는 속도용이라 보안에는 안 씁니다.)*

---

### 우리 Mini Redis에서의 해시(`fnv1a_32`) 역할 요약
> **임의의 키 문자열을 항상 똑같은 32비트 정수로 변환해, 버킷 배열의 방 번호를 빠르고 골고루 정해주는 역할!**
