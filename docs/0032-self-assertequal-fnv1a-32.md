# 0032 · self.assertEqual(fnv1a_32(""), 0x811C9DC5) 이거 계산과정

## Q. self.assertEqual(fnv1a_32(""), 0x811C9DC5) 이거 계산과정을 설명좀

---

핵심은 **`2166136261`(10진수)과 `0x811C9DC5`(16진수)가 완전히 같은 숫자**라는 점입니다!

---

### `fnv1a_32("")` 실행 순서

1. **초기값 설정**
   ```python
   h = _FNV_OFFSET_BASIS  # 2166136261 (16진수로 0x811C9DC5)
   ```
2. **UTF-8 바이트 변환**
   ```python
   "".encode("utf-8")  # 결과: b"" (길이가 0인 빈 바이트열)
   ```
3. **`for` 루프 0번 실행**
   * `b""` 안에 바이트가 하나도 없으므로 `for byte in ...:` 안으로 **아예 들어가지 않고** 바로 빠져나옵니다.
   * 즉 `h ^= byte`도, `_FNV_PRIME` 곱셈도 한 번도 실행되지 않습니다.
4. **반환 & 비교**
   * `return h` → `2166136261` 반환
   * `self.assertEqual(2166136261, 0x811C9DC5)` → 10진수와 16진수 표기만 다를 뿐 **같은 숫자**이므로 `True`(통과)!

---

### 왜 굳이 이 테스트를 넣었을까?
빈 문자열 `""`은 루프가 0번 돌기 때문에, **"FNV-1a의 시작값(`_FNV_OFFSET_BASIS`)에 오타 없이 표준값 `0x811C9DC5`를 정확히 넣었는가?"**를 제일 먼저 검증하는 테스트입니다. *(Watch 창에 `hex(_FNV_OFFSET_BASIS)`를 쳐보시면 `'0x811c9dc5'`가 그대로 나옵니다!)*
