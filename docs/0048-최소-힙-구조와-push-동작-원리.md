# 0048 · 최소 힙 구조와 `push` · `_heapify_up` 동작 원리

## Q. 최소 힙(Min Heap)이 어떻게 생겼고, 배열로 어떻게 트리를 표현하며, `push`와 `_heapify_up`이 어떻게 동작하나요?

---

### 1. 한눈에 보는 비유: “작은 숫자가 꼭대기에 올라가는 피라미드”

최소 힙의 규칙은 딱 하나입니다:
> **“부모(위층)는 항상 자기 자식(아래층)보다 작거나 같아야 한다!”**

- 왼쪽 형제와 오른쪽 형제끼리는 누가 더 작은지 순서를 따지지 않아도 됩니다.
- 그래서 배열 전체를 완벽하게 정렬할 필요 없이, **항상 0번 칸(피라미드 맨 꼭대기)에 가장 작은 값**이 올라와 있게 됩니다.
- Mini Redis에서는 여기에 `(expire_at, key)`를 넣어서 **가장 빨리 만료될 키**가 항상 맨 꼭대기에 오도록 씁니다.

---

### 2. 배열 1줄이 어떻게 피라미드(트리)가 될까요?

파이썬 리스트(`self._items`) 한 줄에 **위층부터, 같은 층에서는 왼쪽부터** 순서대로 번호표를 붙여 놓으면 그대로 피라미드 모양이 됩니다.

```text
배열 인덱스    0   1   2   3
배열의 값     [2,  4,  3,  5]

            2 [0번 칸]          ← 꼭대기(가장 작은 값)
           /          \
      4 [1번 칸]      3 [2번 칸]
      /
  5 [3번 칸]
```

#### 💡 내 바로 위 부모(상사) 위치 공식: `(index - 1) // 2`
- `3번 칸`에 있는 `5`의 부모는? → `(3 - 1) // 2 = 1번 칸(4)`
- `2번 칸`에 있는 `3`의 부모는? → `(2 - 1) // 2 = 0번 칸(2)`

---

### 3. `push(1)`을 하면 벌어지는 일: “막내로 들어가서 상사보다 작으면 승진하기 (`_heapify_up`)”

새 값 `1`을 넣으면, **일단 배열 맨 끝(가장 아래 빈자리)**에 막내로 들어갑니다.  
그다음 바로 위 부모와 비교해서 **내가 더 작으면 서로 자리를 바꾸며 위로 올라갑니다!**

```text
① 맨 끝에 막내로 1 추가      ② 부모(4)보다 작네! 승진!      ③ 부모(2)보다도 작네! 꼭대기!

         2                          2                          1
        / \                        / \                        / \
       4   3                      1   3                      2   3
      / \                        / \                        / \
     5   1                      5   4                      5   4

  [2, 4, 3, 5, 1]            [2, 1, 3, 5, 4]            [1, 2, 3, 5, 4]
```

1. 막내 `1`은 처음에 `4번 칸`에 들어갑니다.
2. 부모 위치 `(4 - 1) // 2 = 1번 칸`을 보니 `4`가 있네요. `1 < 4`이므로 자리를 바꿉니다.
3. 이제 `1번 칸`에 온 `1`의 새 부모 `(1 - 1) // 2 = 0번 칸`을 보니 `2`가 있습니다. `1 < 2`이므로 또 자리를 바꿉니다.
4. `0번 칸`(꼭대기)에 도착했으니 멈춥니다!

---

### 4. 그래서 `peek()`과 `size()`는 엄청 빠릅니다

- **`peek()`:** 꺼내지 않고 살짝 훔쳐보기만 하는 기능 → 그냥 **`0번 칸(self._items[0])`만 읽으면 끝(O(1))!**
- **`size()`:** 현재 몇 개 들어 있는지 → 그냥 **`len(self._items)` 반환!**
