# 0001 · 왼쪽 Pane의 B5-1 전체 계획과 로드맵

## Q. 왼쪽 pane이 짜준 계획은 전체적으로 어떤 내용인가요?

한 줄로 줄이면 **“자료구조 3개를 독립된 부품으로 먼저 만들어 100% 테스트하고, 하나로 합쳐서 작은 Redis를 완성한다”**는 계획입니다.

---

### 1. 단계별 진행 흐름 (10일 완성)

1. **1~3일차 (부품 만들기):**
   - **이중 연결 리스트 (DLL):** 줄 세우기 부품
   - **해시맵 (HashMap):** 빠른 목차/사전 부품
   - **최소 힙 (Min Heap):** 유통기한 알람시계 부품
   - *핵심: 부품마다 단위 테스트(`unittest`)를 붙여 확실히 검증하고 넘어감*

2. **4~6일차 (부품 합체):**
   - `Store` 엔진을 만들고 3개 자료구조를 연결
   - `SET`, `GET`, `DEL`, `EXISTS`, `DBSIZE`, `KEYS` 기본 동작
   - 메모리 초과 시 LRU 자동 제거 (`used_memory`, `maxmemory`, `evicted_keys`)
   - 유통기한 관리 (`EXPIRE`, `TTL`) 및 가짜 시계(`FakeClock`) 테스트

3. **7일차 (대화창 CLI 완성):**
   - `mini-redis>` 프롬프트가 뜨는 대화형 REPL 완성
   - 따옴표를 해석하는 파서(토크나이저)와 표준 에러 4종 처리

4. **8~10일차 (점검 및 발표 준비):**
   - 엣지 케이스 및 Python 3.8 호환성 최종 점검
   - `README.md` 작성 및 동료평가 질문 대비 (모의 인터뷰)

---

### 2. 반드시 지켜야 할 주의사항

- **파이썬 편의 도구 금지:** `dict`, `set`, `collections`, `heapq` 사용 금지 (자료구조 원리 학습 목적)
- **메모리 계산 기준:** 글자 수가 아니라 **UTF-8 바이트 수** 기준 (예: `"한글"`은 2글자지만 6바이트, 따옴표 제외)
- **삭제 경로 단일화:** DEL 삭제, 만료 삭제, LRU 제거가 모두 하나의 삭제 함수(`_remove_key`)를 타야 데이터 불일치 버그가 안 생김
- **실행 환경:** 이 PC에서는 `python` 대신 **`py -3`** 명령어로 실행
