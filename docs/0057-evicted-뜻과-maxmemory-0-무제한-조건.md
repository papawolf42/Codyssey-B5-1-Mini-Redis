# 0057 · `evicted`의 뜻과 `self._maxmemory > 0` 검사 이유

## Q. ① `evicted`가 무슨 뜻인가요? ② `while self._maxmemory > 0 and self._used_memory > self._maxmemory:`에서 왼쪽 조건은 왜 검사하나요?

---

### 1. `evicted`가 무슨 뜻인가요?

- 영어 동사 **`evict`("쫓아내다 / 집세 못 내서 퇴거시키다")**의 과거분사로, **"강제로 쫓겨난"**이라는 뜻입니다.
- 그래서 **`evicted_keys`**는 **"방이 좁아서(메모리 한도 초과로) 저장소가 알아서 쫓아낸 키의 누적 개수"**를 뜻합니다.
- ⚠️ **주의:** 사용자가 직접 `DEL`로 지운 것이나, 유통기한(TTL)이 끝나 자연 소멸한 키는 쫓겨난 게 아니므로 `evicted_keys`에 세지 않습니다!

---

### 2. `while` 조건의 왼쪽 `self._maxmemory > 0`은 왜 검사하나요?

```python
while self._maxmemory > 0 and self._used_memory > self._maxmemory:
```

이 프로젝트의 규칙상 **`maxmemory = 0`은 "메모리 제한 없음(무제한)"**이라는 스위치입니다!  
만약 왼쪽 `self._maxmemory > 0` 검사를 빼버리면 무서운 버그가 터집니다:

- 현재 저장된 메모리가 `22`바이트인데, `maxmemory = 0`(무제한) 상태라고 해봅시다.
- **왼쪽 조건이 없다면?** `22 > 0`이 참(True)이 되어버려서, 무제한인데도 **저장된 모든 키를 0바이트 될 때까지 다 지워버립니다!**
- **왼쪽 조건이 있으면?** `0 > 0`이 거짓(False)이므로 `and` 뒤를 보지도 않고 바로 넘어가서 무제한으로 안전하게 보관합니다.

> **한 줄 요약:** 왼쪽은 **“메모리 제한 스위치가 켜져 있는가?”**, 오른쪽은 **“그 한도를 넘었는가?”**를 묻는 조건입니다!
