# 0060 · `EXPIRE`와 `TTL` 기능 및 `seconds <= 0` 즉시 삭제

## Q. `EXPIRE`와 `TTL`은 어떤 기능이고, `if seconds <= 0:`일 때 왜 바로 지우나요? 그리고 6-a에서는 왜 아직 만료 키가 남아 있나요?

---

### 1. 쉬운 비유: “유통기한 스티커 붙이기(`EXPIRE`)” & “남은 수명 확인(`TTL`)”

- **`EXPIRE key seconds`:** 키에 **"지금부터 몇 초 뒤에 자동으로 버려라"**라는 유통기한 스티커를 붙입니다.
  - 키가 있으면 스티커를 붙이고 **`1`** 반환, 원래 없는 키면 **`0`** 반환.
- **`TTL key` (Time To Live · 남은 수명):** **"이 키 앞으로 몇 초 남았어요?"** 하고 물어보는 명령입니다.
  - **양수 `N` (예: `2`):** `N`초 남음 (소수점은 버림)
  - **`-1`:** 키는 살아 있는데 유통기한 스티커가 안 붙어 있음 (**영구 보관**)
  - **`-2`:** 그런 키가 아예 없거나 이미 유통기한이 지나 사라짐

---

### 2. `if seconds <= 0:`은 왜 즉시 삭제하나요?

`EXPIRE a 0`이나 `EXPIRE a -1`은 **"0초 뒤(지금 당장) / -1초 뒤(이미 1초 전)에 만료되어라"**라는 뜻입니다.  
이미 유통기한이 지난 상태이므로 굳이 힙에 넣을 필요 없이, **`a`가 존재하면 그 자리에서 바로 지우고 `1`**(없으면 `0`)을 돌려주는 거예요.

> ⚠️ **헷갈리지 마세요!**
> - `EXPIRE a -1`의 **`-1`** = 사용자가 입력한 시간 ("1초 전 = 이미 지났으니 바로 지워!")
> - `TTL a`가 돌려주는 **`-1`** = 저장소가 답하는 상태 ("만료 시간 설정 안 됨 = 영구 보관")

---

### 3. 왜 6-a 단계에서는 아직 시간이 지나도 키가 바로 안 사라졌나요?

구현을 두 커밋으로 쪼갰기 때문입니다!
- **6-a (`8151e26`):** `Entry.expire_at`에 만료 시각을 적고 `TTL`로 남은 시간을 계산하는 기능만 먼저 붙임. (`TTL`은 `-2`로 답하지만 힙 정리가 아직 없어 `GET`엔 남아 있던 과도기 상태)
- **6-b (`aa75b6a`):** 최소 힙을 연결해 명령 실행 전마다 만료된 키를 실제로 제거하도록 완성!
