# 0010 · Redis의 네트워크 통신 제약과 REPL의 개념

## Q. "네트워크 통신은 구현하지 않는다"는 제약은 왜 있고, CLI와 REPL은 무엇이 다른가요?

---

### 1. "네트워크 통신은 구현하지 않는다"는 말의 진짜 의미

원래 실제 **Redis는 네트워크 서버 프로그램**입니다.

- 실제 서비스에서는 백그라운드에 `redis-server`를 띄워두고, 웹 서버나 클라이언트(`redis-cli`)가 **TCP 소켓(기본 6379 포트)**으로 접속합니다.
- 이때 데이터를 주고받을 때 **RESP(REdis Serialization Protocol)**라는 전용 통신 프로토콜 바이트 규칙을 사용합니다.
- 반면 우리 과제의 제약("네트워크 통신은 구현하지 않는다, 오직 CLI")은 소켓을 열거나 RESP 프로토콜을 파싱하는 복잡한 네트워크 통신을 만들지 말고, **터미널 안에서 프로그램 1개만 실행해 키보드로 직접 명령을 주고받도록** 만들라는 뜻입니다.

---

### 2. 왜 이런 제약을 걸었을까요?

과제의 본질이 **"자료구조와 알고리즘"**이기 때문입니다.

만약 아무런 제약 없이 *"Mini Redis를 만드세요"*라고 했다면:
- TCP 소켓 서버 열기 (`socket`, `select`, `asyncio`)
- 동시 접속 멀티스레딩 및 락(Lock) 처리
- RESP 네트워크 패킷 파싱
- 디스크 파일 영속성 저장 (RDB / AOF)

위와 같은 네트워크/운영체제 시스템 구현에 수십 시간을 쏟느라 정작 중요한 **HashMap, Doubly Linked List, Min Heap, LRU, TTL** 같은 핵심 알고리즘을 깊이 파지 못하게 됩니다.  
즉, 불필요한 네트워크 잡무를 쳐내고 **순수 자료구조 학습에만 100% 집중하도록** 명확한 경계선을 그어준 것입니다.

---

### 3. CLI와 REPL은 어떻게 다른가요?

#### REPL (Read - Eval - Print - Loop)
대화형 프로그램의 동작 방식을 뜻하는 약어입니다.

1. **Read (읽기):** 사용자가 친 입력을 한 줄 읽어옵니다. (`input("mini-redis> ")`)
2. **Eval (실행/평가):** 입력된 명령어를 해석하고 실행합니다. (예: `SET a 1` → 내부 저장소에 저장)
3. **Print (출력):** 실행 결과를 화면에 보여줍니다. (예: `OK`, `(nil)`)
4. **Loop (반복):** 사용자가 `exit`/`quit`을 칠 때까지 1~3번을 무한히 반복합니다. (`while True:`)

*파이썬을 터미널에서 `py`만 쳐서 들어갔을 때 나오는 `>>> ` 창이 대표적인 REPL입니다.*

#### CLI vs REPL의 포함 관계
- **CLI (Command Line Interface):** 마우스(GUI) 대신 까만 터미널 화면에서 텍스트로 컴퓨터를 다루는 방식 **전체**를 부르는 넓은 말입니다. (`py main.py --help`처럼 한 번 실행되고 바로 끝나는 명령도 CLI입니다.)
- **REPL:** CLI 중에서도 종료되지 않고 프롬프트를 띄운 채 **계속 대화하듯 입출력을 반복하는 대화형 구조**를 구체적으로 부르는 이름입니다.
