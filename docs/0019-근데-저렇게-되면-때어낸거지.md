# 0019 · 근데 저렇게 되면 때어낸거지, node 인스턴스가 사라진건 아닌거아냐?

## Q. 근데 저렇게 되면 때어낸거지, node 인스턴스가 사라진건 아닌거아냐?

---

**정확히 보셨습니다! `_unlink(node)`만으로는 리스트에서 연결만 끊을 뿐, `Node` 객체 자체가 즉시 파괴되지는 않습니다.**

---

### 1. 왜 즉시 안 사라지고 살아남게 짰을까? (두 가지 이유)
1. **호출한 쪽에 "무슨 노드가 빠졌는지" 돌려줘야 하기 때문**
   * `remove_front()`나 `remove_back()`은 뺀 `Node`를 그대로 `return node` 합니다.
   * 나중에 `MiniRedis`가 LRU 제거를 할 때 `node = lru.remove_back()`을 받아서 `node.data`(어떤 키가 쫓겨났는지)를 읽어야 하니까, `return`되는 순간에는 `Node` 인스턴스가 살아 있어야 합니다.
2. **`move_to_front`에서는 떼었다가 재사용하기 때문**
   * `_unlink(node)`로 떼어낸 뒤 바로 `_link_front(node)`로 같은 `Node` 객체를 맨 앞에 다시 붙입니다.

---

### 2. 그럼 메모리에서 영원히 안 사라지나요?
**아닙니다.** 파이썬은 C처럼 `free()`를 직접 부르지 않고 **참조 카운팅(Reference Counting) + 가비지 컬렉터**로 메모리를 해제합니다.

* 리스트에서 `_unlink`로 떼어낸 뒤,
* `node`를 받아둔 변수(`front`, `entry.lru_node` 등)도 사라지거나 덮어씌워져서 **그 `Node`를 가리키는 변수가 0개**가 되면, 파이썬이 **그 즉시 메모리에서 `Node` 인스턴스를 해제**합니다.

#### 여기서 `node.prev = None`, `node.next = None`이 중요한 이유
만약 떼어낸 `node`의 `prev`/`next`를 안 지워두면:
* 호출자가 잠깐 `front = lst.remove_front()`로 `front` 변수만 들고 있어도, `front.next`가 리스트 내부 노드 전체를 계속 붙잡고 있게 됩니다.
* `None`으로 끊어두어야 리스트와 `node`가 완전히 분리되어 불필요한 메모리 점유나 순환 참조가 남지 않고, 안 쓰는 노드가 깔끔하게 수거됩니다.
