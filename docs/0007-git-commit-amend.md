# 0007 · git commit --amend와 브랜치 갈림(ahead/behind)

## Q. git commit --amend를 했는데 왜 커밋이 하나 더 추가된 것처럼 보였나요?

---

### 1. 무슨 일이 일어난 것인가요?

실제로 커밋이 2개로 늘어난 것은 아닙니다.  
로컬 컴퓨터의 `main` 브랜치에는 **단 1개의 커밋**만 존재했습니다.

그런데 왜 2개처럼 보였을까요?

1. 처음에 뼈대 파일들을 만들고 첫 커밋(`53a47b8`)을 생성한 뒤 **GitHub(`origin/main`)에 이미 푸시**했습니다.
2. 이후 로컬에서 코드를 수정하고 `git commit --amend`를 실행했습니다.
3. Git에서 `--amend`는 기존 커밋을 덮어쓰면서 **완전히 새로운 커밋 번호(해시: `64f8e41`)**를 만들어냅니다.

---

### 2. 브랜치가 갈라진 상태 (Diverged: ahead 1, behind 1)

이 시점에서 Git의 시선은 다음과 같았습니다:

- **내 로컬 컴퓨터:** 새 커밋 `64f8e41` (1개)
- **GitHub 원격 저장소:** 옛날 커밋 `53a47b8` (1개)

GitHub에는 옛날 커밋이 남아있고, 로컬에는 새 커밋이 있으니 Git은 서로 다른 커밋 1개씩을 가진 상태로 보고 **"1개 앞서 있고 1개 뒤처져 있음(ahead 1, behind 1)"**이라고 안내한 것입니다.

---

### 3. 해결 방법: force push

혼자 작업하는 개인 저장소이고 첫 커밋의 내용을 정정한 것이므로,  
`git push --force-with-lease origin main` 명령어를 통해 원격 저장소의 옛날 커밋을 로컬의 새 커밋(`64f8e41`)으로 깔끔하게 덮어써서 동기화했습니다.
