그림으로 술술 이해하는 Mini Redis

어려운 개발 용어는 잠깐 내려놓고, “컴퓨터 안에 초고속 사물함을 만든다”고 생각해 볼게요. 이 페이지 하나만 끝까지 읽으면 전체 구조와 Entry, MRU/LRU, DLL, Min Heap, 그리고 SET/GET 같은 명령어까지 한 번에 연결됩니다.

STEP 1 · 질문부터 바로 풀기

Q1. user:2에서 콜론(:)은 Redis 문법인가요?

아니요, 문법이 아니라 사람들이 정한 “이름 짓기 약속”이에요!

실제 회사나 개발자들이 Redis에 데이터를 넣을 때, 키 이름이 1, 2, apple처럼 섞이면 헷갈리니까 “이건 user(회원) 데이터 중 2번이야”라는 뜻으로 가운데에 콜론(:)을 붙여서 "user:2"라고 자주 적습니다.

컴퓨터 눈에는 그냥 평범한 글자예요 프로그램 입장에서는 "user:2"나 "user_2"나 "철수"나 똑같은 문자열(글자)입니다. 콜론이 특별한 명령이나 문법 기능을 하지는 않아요!

Q2. 결국 핵심 키워드 3개로 Redis를 만든다고 생각해도 될까요?

네, 맞습니다! 딱 3가지 부품으로 만든다고 생각하면 됩니다.
다만 이름만 살짝 바로잡자면, least heap이 아니라 Min Heap(최소 힙)이라고 부릅니다.

STEP 2 · 큰 그림

Redis를 움직이는 3가지 핵심 부품 (도서관 비유)

우리가 만들 Mini Redis는 메모리가 한정된 작은 도서관과 비슷합니다. 이 도서관이 빠르고 똑똑하게 돌아가려면 직원 3명(자료구조 3개)이 각자 한 가지 일만 맡아서 협력합니다.

부품 1 · 빠르게 찾기

HashMap (해시맵)

역할: 도서관 색인 카드 / 사물함 번호표.
"user:2"라고 이름만 부르면, 몇만 개가 있어도 1초 만에 그 사물함이 어디 있는지 찾아줍니다.

부품 2 · 자리 비우기

Doubly Linked List (DLL)

역할: 최근에 쓴 순서대로 줄 세우기.
방금 쓴 건 맨 앞(MRU), 오래 안 쓴 건 맨 뒤(LRU)로 보내서, 방이 꽉 차면 맨 뒤부터 내보냅니다.

부품 3 · 유통기한 관리

Min Heap (최소 힙)

역할: 유통기한 알람시계.
“몇 초 뒤에 지워져야 하는지”를 모아두고, 가장 빨리 상할 물건을 항상 맨 꼭대기에 올려 감시합니다.

왜 굳이 3개나 쓰나요? HashMap은 찾기는 엄청 빠른데 “누가 제일 오래됐는지” 모르고, DLL은 순서는 잘 아는데 “특정 이름 찾기”가 느리고, Min Heap은 “가장 빠른 유통기한”만 기가 막히게 잘 찾습니다.
그래서 각자 잘하는 것만 맡겨서 서로 손잡고 일하게 만든 거예요!
STEP 3 · Entry란 무엇인가

Entry는 정보를 한데 묶어 담은 “보관 상자”예요

보통 사물함에는 "user:2" → "Bob"처럼 값("Bob") 하나만 넣을 것 같죠? 그런데 우리 사물함은 ① 실제 값도 기억해야 하고, ② 유통기한도 기억해야 하고, ③ 줄에서 몇 번째인지도 기억해야 합니다.

그래서 이 3가지를 하나의 작은 상자에 묶어 넣고, 그 상자를 영어 단어로 Entry(엔트리, 한 건의 기록)라고 부릅니다.

Entry는 “값 + 만료 시각 + 줄에서의 내 위치” 3개를 담아두는 한 세트 상자입니다.
상자 속 이름 쉬운 뜻 왜 들어있나요?
value 저장한 실제 내용 GET user:2라고 물었을 때 "Bob"이라고 답해주기 위해서입니다.
expire_at 사라질 예정 시각 예를 들어 지금이 100초이고 3초 뒤 만료면 103.0이 적혀 있습니다. 유통기한이 없으면 비어있음(None).
lru_node 줄 서기 표지판(위치 주소) 가장 중요한 아이디어! 이 주소 덕분에 DLL 줄에서 "user:2"를 찾아 헤매지 않고, 바로 손잡고 맨 앞으로 끌어올 수 있습니다.
STEP 4 · 전체 조감도

3가지가 하나로 연결된 전체 그림

이제 방금 배운 HashMap, Entry, DLL (MRU ↔ LRU), Min Heap이 한 화면에서 어떻게 연결되는지 보세요. (현재 user:3, user:2, user:1이 저장되어 있고, user:2에 만료 시간이 걸린 상태입니다.)

초록 점선/실선이 바로 Entry.lru_node입니다! HashMap에서 Entry를 찾으면, DLL 줄에서 그 키가 어디 있는지 바로 점프할 수 있어요.
STEP 5 · DLL, MRU, LRU 낱낱이 이해하기

줄 서기(DLL)와 MRU / LRU가 어떻게 움직이나요?

단어부터 풀고 갈게요. 겁먹을 것 하나도 없는 영어 줄임말입니다!

  • DLL (Doubly Linked List · 이중 연결 리스트): 각 칸(노드)이 앞사람 주소(prev)와 뒷사람 주소(next)를 양손으로 잡고 서 있는 줄입니다.
  • MRU (Most Recently Used): “가장 최근에 사용됨” → 방금 누가 찾았으니 줄 맨 앞으로 보냅니다.
  • LRU (Least Recently Used): “가장 오랫동안 안 쓰임” → 아무도 안 찾아서 밀려난 줄 맨 뒤. 공간이 모자라면 여기서부터 내보냅니다.
왜 굳이 양손(이중 연결 리스트)을 잡나요? 줄 중간에 있던 user:1을 맨 앞(MRU)으로 옮기려면, 먼저 user:1을 줄에서 쏙 빼야 하죠?
이때 user:1이 자기 앞사람(prev)과 뒷사람(next)을 알고 있으면, “내 앞사람과 뒷사람을 서로 손잡아 주기”만 하면 끝나요! 데이터가 100만 개 있어도 순식간(O(1))입니다.

실제 상황 그림: GET user:1을 실행하면 벌어지는 일

방금 조회한 user:1은 맨 앞(MRU)으로 살아남고, 대신 아무도 안 찾은 user:2가 맨 뒤(LRU)가 되었습니다.
STEP 6 · Min Heap과 expire_at

유통기한 감시: Min Heap과 expire_at

어떤 키에는 EXPIRE user:2 3처럼 “3초 뒤 자동으로 없어져라”라는 유통기한을 걸 수 있습니다.

이때 현재 시각이 100초라면, 상자(Entry) 안의 expire_at 칸에 103초라고 적어두고, Min Heap(최소 힙)이라는 피라미드에 (103초, "user:2")를 넣어둡니다.

왜 Min Heap이 편한가요? 만료 시간이 걸린 키가 1만 개 있어도 전부 뒤질 필요가 없어요.
항상 맨 꼭대기(peek()) 하나만 쳐다보고 “지금 시간보다 작아졌으면 버리고, 아직 안 됐으면 나머지 9,999개도 아직 멀었구나!” 하고 넘어가면 됩니다.

STEP 8 · 명령어 사전

SET, GET, DEL… 다 처음 봐도 괜찮아요!

명령어가 많아 보여도, 결국 “넣고, 꺼내고, 지우고, 몇 개인지 세고, 유통기한 거는 것” 딱 10개뿐입니다. 하나씩 순서대로 만들어 가면 됩니다.

① 기본 데이터 명령어 (6개)

명령어 우리말 뜻 예시와 결과 내부에서 무슨 일이?
SET key value 저장하기 (덮어쓰기) SET user:1 "Alice" → OK HashMap에 Entry 저장 + DLL 맨 앞(MRU)으로 이동 + 메모리 넘치면 LRU 제거
GET key 꺼내 보기 (조회) GET user:1 → "Alice"
(없으면 (nil))		 HashMap에서 찾기 → 있으면 값 보여주고 DLL 맨 앞(MRU)으로 이동
DEL key 삭제하기 DEL user:1 → (integer) 1
(원래 없으면 0)		 HashMap과 DLL에서 모두 지우고 사용 메모리에서 빼기
EXISTS key 있는지 확인하기 EXISTS user:1 → 1 또는 0 만료 안 된 키가 HashMap에 살아있으면 1, 없으면 0
DBSIZE 총 몇 개 있나? DBSIZE → (integer) 2 만료된 키를 먼저 정리한 뒤, 현재 남아 있는 키 개수 세기
KEYS 전체 이름표 목록 KEYS → 1. "user:2", 2. "user:3" 현재 살아 있는 모든 키 이름 보여주기 (순서 상관없음)

② 메모리 관리 명령어 (2개)

명령어 우리말 뜻 예시와 결과
CONFIG SET maxmemory 숫자 최대 메모리 용량 정하기 (바이트) CONFIG SET maxmemory 30 → OK (0이면 무제한)
INFO memory 메모리 성적표 보기 used_memory:22 / maxmemory:30 / evicted_keys:1(쫓겨난 수)

③ 유통기한(TTL) 명령어 (2개)

명령어 우리말 뜻 결과 숫자 의미
EXPIRE key 초 “몇 초 뒤에 자동 삭제해줘” 성공하면 (integer) 1, 없는 키면 (integer) 0
TTL key “얼마나 남았어?” (Time To Live) 양수(예: 2): 2초 남음
-1: 키는 있는데 유통기한을 안 걸었음(영구)
-2: 그런 키가 없음 (또는 이미 만료돼서 사라짐)
STEP 9 · unittest와 차근차근 로드맵

unittest는 어렵지 않아요! “자동 확인 버튼”이에요

코드가 조금만 길어져도 수정할 때마다 직접 SET, GET을 손으로 쳐서 확인하기는 힘듭니다. 파이썬에 기본으로 들어 있는 unittest는 내가 미리 적어둔 확인 목록을 버튼 한 번(py -m unittest)으로 대신 검사해주는 도구입니다. 

# 예: "1을 넣고 2를 넣으면, 꺼낼 때 제대로 나오는지" 자동 검사하기
import unittest

class TestSimple(unittest.TestCase):
    def test_add(self):
        result = 1 + 2
        self.assertEqual(result, 3)  # "result가 3과 같아야 통과!"

# 터미널에서 실행: py -m unittest

우리가 앞으로 밟아갈 아주 쉬운 순서

한 번에 다 이해하고 짜려 하지 말고, 레고 블록 1개씩 만들고 검사하면서 올라가면 됩니다.

순서 무엇을 만드나요? 완료 기준 (쉽게 말하면)
1단계 폴더 만들기 + unittest 실행해보기 가짜 테스트 1개가 OK로 통과하면 끝!
2단계 DLL (줄 세우기 부품) 맨 앞 추가, 맨 뒤 삭제, 중간에서 맨 앞으로 이동이 잘 되는지 테스트
3단계 HashMap (목차 부품) put, get, remove가 잘 되고, 칸이 차면 2배로 커지는지 테스트
4단계 Min Heap (알람시계 부품) 숫자를 아무 순서로 넣어도 pop할 때 작은 숫자부터 나오는지 테스트
5단계 Store (3개 부품 합체!) SET, GET, DEL, EXISTS, DBSIZE, KEYS + LRU + 메모리 계산 연결
6단계 TTL (유통기한 연결) 가짜 시계로 시간을 3초 앞으로 돌렸을 때 user:2가 사라지는지 확인
7단계 CLI (mini-redis> 입력창) 키보드로 명령어를 입력하면 Redis처럼 OK, (nil)이 출력되게 완성!
지금 당장 할 수 있는 가장 작은 첫 걸음 이 그림으로 큰 흐름이 잡혔다면, 다음은 왼쪽이나 오른쪽 에이전트에게 “1단계: 빈 폴더랑 unittest 예제 1개만 먼저 같이 만들어보고 실행해 보자”라고 하시면 아주 가볍게 시작할 수 있습니다!
