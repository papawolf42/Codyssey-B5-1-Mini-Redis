# 0013 · 센티널 노드를 둔다는데서 센티널의 어원이 뭐야? Node 클래스에선 next prev를 직

## Q. 센티널 노드를 둔다는데서 센티널의 어원이 뭐야? Node 클래스에선 next prev를 직접쓰면서, DLL 클래스에서는 왜 _head _tail과 같은 언더바를 쓰는거야?

---

### 1. 센티널(Sentinel)의 어원
영어 **sentinel**은 **"보초, 파수꾼, 감시병"**이라는 뜻입니다.
* **어원:** 라틴어 *sentīre*(감지하다, 지키다) → 중세 프랑스어 *sentinelle*(초병, 보초)에서 왔습니다.
* **왜 자료구조에서 이 단어를 쓸까?**
  * 리스트의 양 끝에 실제 데이터는 없지만 **보초병처럼 딱 서서 경계(`head`, `tail`)를 지켜주는 가짜 노드**라는 뜻입니다.
  * 양 끝에 보초가 서 있기 때문에 실제 데이터가 0개든 1개든 가운데 노드는 항상 앞뒤에 노드가 존재하고, 그래서 *"여기가 맨 끝(`None`)인가?"*를 검사하는 `if`문이 사라집니다. (같은 뜻으로 **더미(Dummy) 노드**라고도 부릅니다.)

---

### 2. 왜 `Node`는 `prev`/`next`이고, `DoublyLinkedList`는 `_head`/`_tail`일까?
파이썬(PEP 8)에서 **앞에 `_` 하나를 붙이는 건 "클래스 내부 전용(private)이니 밖에서 직접 만지지 마세요"라는 약속**입니다.

1. **`DoublyLinkedList`의 `_head`, `_tail`, `_size`에 `_`를 붙인 이유**
   * `DoublyLinkedList`를 쓰는 쪽(`MiniRedis`, `HashMap`)은 `insert_front()`, `remove_node()`, `size()` 같은 **공개 메서드만** 써야 합니다.
   * 밖에서 `lst._size = 99`나 `lst._head = None`처럼 직접 건드리면 리스트 불변식이 깨지기 때문에 *"내부 상태이니 직접 접근하지 말라"*는 의미로 `_`를 붙입니다.
   * *(테스트의 `_backward_data`에서 `lst._tail.prev`를 읽은 건 `prev` 포인터가 꼬이지 않았는지 확인하기 위해 테스트에서만 예외적으로 내부를 들여다본 것입니다.)*

2. **`Node`의 `prev`, `next`, `data`에 `_`를 안 붙인 이유**
   * `Node`는 `DoublyLinkedList`와 `MiniRedis`가 **밖에서 직접 읽고 조작하는 부품(단순 구조체)**입니다.
     * `DoublyLinkedList`는 남의 클래스인 `Node`의 `node.prev`, `node.next`를 직접 이어 붙여야 합니다.
     * 나중에 `MiniRedis`도 `entry.lru_node.data`로 키 이름을 꺼내 읽어야 합니다.
   * 즉 `DoublyLinkedList` 입장에선 `Node`의 필드들이 **다른 클래스가 접근하는 공개(public) 인터페이스**이기 때문에 `_`를 붙이지 않습니다. (만약 `_prev`, `_next`로 만들면 `DoublyLinkedList`가 매 줄마다 남의 private 속성 `node._prev._next`를 건드리는 꼴이 되어 관례에도 어긋나고 읽기도 지저분해집니다.)
