# 0061 · 만료 지연 삭제(Lazy Deletion)와 `entry` 검증 조건의 비밀

## Q. `if entry is not None and entry.expire_at == expire_at:` 조건에서 왼쪽과 오른쪽이 왜 둘 다 필요한가요? `DEL`하면 힙에는 기록이 남는데 어떻게 처리되나요?

---

### 1. 한눈에 보는 비유: “옛날 알람을 미리 끄지 않고, 울릴 때 달력 보고 무시하기”

약속 시간이 10시 3분에서 10시 10분으로 바뀌었다고 해볼게요.  
알람시계 피라미드(최소 힙) 속에 깊숙이 박혀 있는 옛날 알람(10시 3분)을 굳이 뒤져서 끄려면 시간이 오래 걸립니다(**O(N)**).

대신 우리는 **지연 삭제(Lazy Deletion)**라는 게으르지만 똑똑한 전략을 씁니다:
- **힙(알람시계)에는 그냥 새 알람만 추가해 두고, 옛 알람은 내버려 둔다.**
- 나중에 그 **옛 알람이 맨 위로 올라와서 울릴 때**, 진짜 장부(**해시맵**)를 쓱 보고 *"어? 이거 이미 취소됐거나 시간이 바뀐 옛날 알람이네?"* 하고 조용히 무시해서 버린다!

---

### 2. 그래서 꼭 필요한 2가지 검증 조건 (`and` 좌우)

```python
if entry is not None and entry.expire_at == expire_at:
    self._remove_key(key)
```

#### ① 오른쪽 조건 (`entry.expire_at == expire_at`) — “연장된 옛 알람 거르기”
- 시각 `100`에 `EXPIRE a 3` → 힙에 `(103, "a")` 추가, 해시맵 `a.expire_at = 103`
- 시각 `101`에 `EXPIRE a 10` → 힙에 `(111, "a")` 또 추가! **(힙에는 `(103, "a")`와 `(111, "a")` 2개가 공존!)**, 해시맵 `a.expire_at = 111`
- **시각 `103`에 알람이 울려 `(103, "a")`를 꺼냈을 때:**  
  해시맵의 진짜 만료 시각(`111`)과 알람 시각(`103`)이 다르네요! → **거짓이므로 `a`를 지우지 않고 옛 알람만 버림!**

#### ② 왼쪽 조건 (`entry is not None`) — “이미 `DEL`로 지운 키 거르기”
만료를 **한 번만** 걸었어도 이 왼쪽 조건이 없으면 에러가 터집니다!
- 시각 `100`에 `SET a hello`, `EXPIRE a 3` → 힙에 `(103, "a")`
- 시각 `101`에 **`DEL a`** → 해시맵과 LRU에서는 `a`가 즉시 삭제됨. 하지만 힙은 건드리지 않았으므로 `(103, "a")`가 남아 있음!
- **시각 `103`에 다른 명령(`GET b`)이 들어와 힙에서 `(103, "a")`를 꺼냈을 때:**  
  `entry = self._map.get("a")`를 해보니 이미 삭제되어 **`None`**이 나옵니다!
  - 왼쪽 `entry is not None`이 거짓이므로 파이썬은 오른쪽 `entry.expire_at`을 읽지 않고(즉 **`None.expire_at` 에러 방지**), 옛 알람만 조용히 버리고 `GET b`를 계속 처리합니다!
