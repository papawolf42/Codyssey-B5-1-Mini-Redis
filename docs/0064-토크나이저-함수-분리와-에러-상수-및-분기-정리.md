# 0064 · 토크나이저 함수 분리, 에러 상수 모음, `execute` 분기 정리

## Q. 토크나이저(`tokenize`)를 왜 2개 함수로 쪼갰고, 에러 문구 5개를 왜 상단에 모았으며, `execute` 분기는 어떻게 정리했나요?

---

### 1. 토크나이저를 `tokenize` + `_read_token` 두 함수로 나눈 이유

처음엔 `in_quote`, `token_started` 같은 상태 변수 2개를 한 루프에 다 넣다 보니, 짧긴 해도 한눈에 읽히지 않았습니다.  
그래서 **"공백을 건너뛰는 역할"**과 **"단어 1개를 읽는 역할"**로 쪼개 책 읽듯 쉽게 바꿨습니다:

- **`tokenize(line)`:** 공백은 건너뛰고, 글자가 나오면 `_read_token()`에 단어 하나 읽어오기를 맡긴 뒤 결과 리스트에 담습니다.
- **`_read_token(line, index)`:**
  - 큰따옴표(`"`)를 만나면 닫는 따옴표가 나올 때까지 **그 안의 공백까지 통째로** 읽어옵니다. (그래서 `SET msg "hello world"`가 3조각으로, `SET k ""`도 빈 문자열 토큰으로 잘립니다.)
  - 일반 글자면 다음 공백이 나올 때까지 읽습니다.
  - 닫는 따옴표 없이 줄이 끝나면 `ValueError`를 내서 syntax error로 처리합니다.

---

### 2. 에러 문구 5개를 `commands.py` 맨 위에 모아둔 이유

```python
_SYNTAX_ERROR = "(error) ERR syntax error"
_UNKNOWN_COMMAND = "(error) ERR unknown command '{name}'"
_WRONG_ARG_COUNT = "(error) ERR wrong number of arguments for '{name}' command"
_NOT_INTEGER = "(error) ERR value is not an integer or out of range"
_OOM = "(error) OOM command not allowed when used_memory > 'maxmemory'"
```

1. **한 화면 설명 가능:** 평가에서 *"에러 문구 어디에 있나요?"*라고 물으면 이 5줄만 보여주면 바로 답할 수 있습니다.
2. **오타·유지보수 방지:** 여러 함수에 흩어져 있지 않고 한 곳에서만 관리합니다.
3. **금지 리터럴(`{}`) 오탐 회피:** 빈 `{}` 대신 `{name}`처럼 이름 있는 자리를 쓰면, 나중에 8-3 점검에서 빈 딕셔너리 리터럴(`{}`) 검사에 잘못 걸리지 않습니다.

---

### 3. `execute`의 명령어 분기 정리

인자 수를 담는 표와 도우미 함수를 분리해, `execute()` 안의 `if` 문에서는 **`SET`이면 `_set`, `GET`이면 `_bulk`, `DEL`이면 `_integer`**처럼 명령마다 **딱 한 줄씩 무슨 일을 하는지만 깔끔하게 보이도록** 정리했습니다.
