# 0006 · from __future__ import annotations의 역할과 제거 이유

## Q. from __future__ import annotations는 왜 넣었었고, 왜 다시 뺐나요?

---

### 1. 원래 왜 넣었었나요?

파이썬 3.10 이상에서는 타입 힌트를 쓸 때 `Node | None`처럼 간결하게 적을 수 있습니다.  
하지만 우리 과제는 **Python 3.8 이상** 호환이 필수입니다. 3.8 환경에서 `Node | None`을 그대로 실행하면 파이썬이 문법 오류를 내며 멈춥니다.

파일 맨 위에 `from __future__ import annotations`를 넣어두면, 파이썬이 타입 힌트를 즉시 계산하지 않고 문자열 메모처럼 취급하여 이전 버전에서도 에러를 막아주는 역할을 합니다.

---

### 2. 왜 다시 지우기로 결정했나요?

1. **타입 힌트를 아예 쓰지 않기로 결정:**  
   우리 프로젝트에서는 코드의 복잡성을 줄이고 직관적인 이해를 돕기 위해 코드에 타입 힌트를 쓰지 않고, 인자와 반환값 설명을 일반 **docstring(설명 주석)**에 적기로 합의했습니다.
2. **타입 힌트가 없으면 저 구문도 불필요:**  
   타입 힌트를 쓰지 않는 순수 파이썬 코드에서는 클래스 안에서 자기 자신을 생성하거나 반환해도 Python 3.8에서 전혀 에러가 나지 않습니다.
3. **동료평가(Peer Evaluation) 대비:**  
   동료평가관이 *"코드 맨 위에 이 줄은 왜 들어있나요?"*라고 질문했을 때, 과제 핵심(자료구조)과 상관없는 3.10 지연 평가 문법까지 설명해야 하는 불필요한 부담을 없앴습니다.

👉 **결론:** 3.8 호환성은 `match`, `removeprefix`, `|` 같은 3.9+ 문법을 쓰지 않는 것만으로 충분히 달성됩니다.
