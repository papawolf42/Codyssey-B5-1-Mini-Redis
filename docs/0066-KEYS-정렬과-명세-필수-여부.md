# 0066 · `KEYS` 출력 정렬은 명세의 필수 요구사항일까?

## Q. `KEYS` 결과를 이름순(`sorted`)으로 정렬해서 출력하는 변경이 `instruction.md`에 나와 있나요?

---

### 1. 한 줄 결론

> **정렬 자체는 명세의 “필수 요구사항”이 아니지만, 명세에 어긋나지 않으면서 출력이 매번 일정해져 테스트와 시연이 훨씬 깔끔해지는 좋은 선택입니다!**

---

### 2. `instruction.md` 원문 기준 확인

- **`KEYS` 요구사항 (`instruction.md` 4-2장):**  
  > 전체 키 목록을 배열 형태로 출력 **(정렬/순서는 요구하지 않음)**
- **8장 실행 예시:**  
  `1. "user:2"`, `2. "user:3"`으로 나와 있지만, 어디까지나 참고 예시이므로 순서까지 똑같이 맞출 의무는 없습니다.
- **참고 · CLI REPL 연결 (`168dbd8`):**  
  반면 `mini-redis>` 프롬프트를 띄워 명령을 실행하고 `exit`/`quit`으로 종료하는 CLI 연결은 **4-5장의 필수 요구사항**입니다.

---

### 3. 왜 정렬(`sorted(store.keys())`)을 추가했을까요?

원래 해시맵의 `keys()`는 0번 버킷부터 끝 버킷까지 훑어 모으기 때문에, **버킷 크기나 해시값에 따라 키 순서가 들쭉날쭉** 나옵니다.  
여기에 `sorted(...)`를 한 번 감싸주면 **언제 실행해도 항상 같은 가나다/ABC 순으로 나와** 사람이 눈으로 확인하거나 테스트 코드를 짜기가 훨씬 편해집니다!
