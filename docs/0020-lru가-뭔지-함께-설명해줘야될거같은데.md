# 0020 · LRU가 뭔지 함께 설명해줘야될거같은데

## Q. LRU가 뭔지 함께 설명해줘야될거같은데

---

**LRU (Least Recently Used)**는 **"가장 오랫동안 사용되지 않은 것부터 버린다"**는 캐시 제거 정책입니다.

---

### 1. 직관적인 비유 (책상 위 공간)
책상 위에 책을 최대 **3권**만 올려둘 수 있다고 생각해 보세요.
1. `A`, `B`, `C` 순서로 책을 올려둡니다.
   * 최근 본 순서 (앞=최신 → 뒤=오래됨): **`[C, B, A]`**
2. 이때 오래된 `A`를 다시 펼쳐 읽으면, `A`는 **"방금 본 책"**이 되므로 맨 앞으로 옵니다.
   * **`[A, C, B]`**
3. 이제 새 책 `D`를 올리려는데 자리가 없으면? **가장 오랫동안 손대지 않은 맨 뒤의 `B`**를 내립니다.
   * **`[D, A, C]`** (`B` 제거)

*"방금 쓴 데이터는 곧 다시 쓸 확률이 높고, 오랫동안 안 찾은 데이터는 덜 중요할 것"*이라는 원리입니다.

---

### 2. Mini Redis에서 언제 쓰이나?
[instruction.md](file:///C:/Users/alsgu/Dev/Codyssey/B5-1/instruction.md#L173-L178)에서 `CONFIG SET maxmemory`로 메모리 한도를 정해 두었을 때:
* `SET`이나 `GET`에 성공한 키는 **방금 사용됨 → 맨 앞**으로 보냅니다.
* 새 키를 `SET`하다가 `used_memory`가 `maxmemory`를 넘으면, **맨 뒤에 있는(가장 오래 안 쓴) 키부터 하나씩 지워서** 메모리를 확보합니다. *(이게 아까 말씀드린 `evicted_keys`로 카운트되는 제거입니다.)*

---

### 3. 지금 만드는 `DoublyLinkedList`가 바로 이 LRU 줄 세우기 용도입니다!
`DoublyLinkedList`를 **사용 순서 줄 세우기**로 쓰면 모든 LRU 동작이 **O(1)**에 끝납니다:
* **앞쪽(`_head` 쪽)** = 방금 사용한 최신 키
* **뒤쪽(`_tail` 쪽)** = 가장 오래 안 쓴 제거 후보 키

그래서 우리가 메서드를 딱 이렇게 만들고 있는 겁니다:
1. 새 키 저장(`SET`) → **`insert_front`** (최신이니 맨 앞에 세움)
2. 기존 키 조회(`GET`) / 덮어쓰기(`SET`) → **`move_to_front`** (줄 중간에 있던 노드를 바로 떼서 맨 앞으로 끌어올림)
3. 메모리 초과 시 제거 → **`remove_back`** (맨 뒤에 서 있던 가장 오래된 키를 꺼내 제거)
4. 키 직접 삭제(`DEL`) → **`remove_node`** (해시맵이 기억하던 `lru_node`를 바로 떼어냄)

*(참고: 단일 연결 리스트나 파이썬 `list`로는 중간 원소를 떼서 맨 앞으로 옮기거나(`move_to_front`), 맨 뒤를 뺄 때(`remove_back`) O(n)이 걸리기 때문에 **O(1)**을 지키려고 `prev`/`next` 양방향 포인터를 가진 이중 연결 리스트를 쓰는 것입니다.)*
